# Skills

이 폴더는 이 워크스페이스 전용 스킬을 담습니다.

## Skills란?

Skills는 Claude Code가 **키워드 기반으로 자동 트리거**하는 기능 모음입니다.
구 슬래시 커맨드 방식(`/daily-note`)을 대체합니다.

- 자연어 호출: "오늘 daily note 만들어줘"
- Claude가 description에 있는 키워드를 감지하여 자동 실행
- 각 스킬은 `SKILL.md`를 루트에 두고, 필요시 `scripts/`, `resources/` 같은 하위 폴더 사용

## 파일 구조

```
.claude/skills/
├── README.md             # 이 파일
└── [skill-name]/
    ├── SKILL.md          # 스킬 정의 (YAML frontmatter + 설명 + 실행 절차)
    ├── scripts/          # (선택) 실행 스크립트
    └── resources/        # (선택) 참고 자료, 템플릿
```

## SKILL.md 구조

```yaml
---
name: skill-name
description: 이 스킬이 언제 트리거되는지 명확히. "X를 언급하면 자동 실행" 형식 권장.
---

# 스킬 제목

본문 — 실행 절차, 예시, 주의사항
```

## 전역 vs 프로젝트 스킬

- **전역**: `~/.claude/skills/` — 모든 프로젝트에서 적용
- **프로젝트**: 이 폴더 — 이 워크스페이스에서만 적용

이름이 같은 스킬이 양쪽에 있으면 **전역 것이 먼저 걸립니다.** 이 폴더의 스킬을 쓰려면 전역 쪽의 같은 이름 스킬을 치우거나 이름을 바꿉니다.

## 포함된 스킬 (21개)

이름을 외울 필요는 없습니다. 한국어로 말하면 걸립니다 — "카톡 읽어줘" 하면 `kakao-read`가 뜹니다.
아래 **부르는 말**은 그 스킬이 확실히 걸리는 문장이고, 비슷하게 말해도 대개 걸립니다.

### 처음 한 달에는 이 다섯 개만

21개를 다 보면 아무것도 안 쓰게 됩니다. 매일 쓰는 것부터 몸에 붙이세요.

1. `setup-workspace` — 받은 직후 딱 한 번. 이걸 안 하면 다른 스킬이 폴더를 못 찾습니다
2. `daily-note` — 오늘 업무일지를 정해진 폴더에 만듭니다. 하루의 시작
3. `todo` — "이거 해야 해" 한 마디로 할 일이 담깁니다
4. `thinking-partner` — 답이 아니라 질문이 필요할 때. 뭘 해야 할지 모르겠을 때
5. `ripple` — 대화를 닫기 전에 한 번. 이 대화에서 남길 것이 노트·진행 기록·할 일에 빠짐없이 나뉘어 적힙니다

나머지는 필요한 일이 생겼을 때 아래에서 찾으세요.

매일·매주 쓰는 스킬들이 서로 어떻게 이어지는지는 [`00-system/03-guides/운영-스킬-가이드.md`](../../00-system/03-guides/운영-스킬-가이드.md)에 한 장으로 모아 두었습니다.

### 내 것 가져오기

#### 카톡 읽기 · `kakao-read`
내 컴퓨터 안에 있는 카카오톡에서 대화·사진·파일을 직접 읽어 옵니다. 카카오 서버에 접속하지 않습니다. 요약·검색·할 일 뽑기까지 한 번에 합니다.
- **부르는 말** "카톡 읽어줘" · "어제 그 방 대화 정리해줘" · "카톡에서 그 파일 찾아줘" · "카톡 체크"
- **조심할 것** 읽기 전용입니다 — 보내기·삭제는 안 됩니다. 사진·파일은 **보낸 지 3일 안쪽만** 받아집니다(카카오 정책이라 못 고칩니다). Mac은 `brew install sqlcipher`가 먼저고, 윈도우는 **카톡이 켜져 있어야** 합니다
- **누구에게** 영업·CS · 매장·자영업 · 팀장·관리자 · 총무·행정

### 조사하기

#### 네이버 검색 데이터 · `naver-search`
네이버 블로그·카페 글과 검색량을 정식 API로 가져옵니다. 이 키워드가 한 달에 몇 번 검색되는지, 사람들이 같이 검색하는 말이 뭔지, 글이 얼마나 쌓였는지가 숫자로 나옵니다.
- **부르는 말** "검색량 조회" · "연관키워드 뽑아줘" · "카페 수요 조사" · "키워드 경쟁강도"
- **조심할 것** 처음 한 번 키 발급이 필요합니다. 검색·트렌드만 쓰면 네이버 API HUB 하나, 검색량·연관키워드까지 쓰려면 검색광고 API도. **키는 본인 계정으로** 받으세요 — 남의 키를 쓰면 계정 공유가 됩니다
- **누구에게** 마케팅·홍보 · 이커머스·MD · 기획·전략 · 대표·창업

#### 리뷰 분석 · `review-analyzer`
네이버 리뷰를 로그인 없이 모아 4단계로 분석합니다. 무엇이 좋았고 무엇이 걸렸는지, 그래서 다음에 뭘 바꿀지까지 나옵니다. 상품 리뷰(브랜드스토어)와 매장 리뷰(플레이스·지도) 둘 다 됩니다.
- **부르는 말** "네이버 리뷰 분석해줘" · "경쟁사 리뷰 봐줘" · "우리 매장 플레이스 리뷰"
- **조심할 것** 상품 리뷰는 Chrome 브라우저가 필요합니다(selenium). 매장 리뷰는 아무것도 필요 없습니다
- **누구에게** 이커머스·MD · 매장·자영업 · 마케팅·홍보 · CS·품질

#### 막힌 페이지 열기 · `web-bypass`
그냥은 안 열리는 페이지를 일반 요청 → Aside 안에서 요청 → Aside 탭으로 열기 순서로 받아 옵니다. 한 번 가져온 것은 하루 동안 저장해 두고 다시 씁니다.
- **부르는 말** "403이야 뚫어줘" · "차단됐는데 내용 가져와줘"
- **조심할 것** Aside가 깔려 있고 켜져 있어야 뒤의 두 단계가 돕니다(없으면 일반 요청만). Aside로 받은 내용은 **내 로그인으로 보이는 화면**입니다. 잘 열리는 주소에는 쓰지 않습니다
- **누구에게** 마케팅·홍보 · 기획·전략 · 이커머스·MD · 대표·창업

### 문서 바꾸기

#### PDF → 글 · `pdf-to-md`
PDF를 표·제목·문단 구조를 살린 채 텍스트로 바꿉니다. 그냥 열어 읽는 것보다 표가 안 깨지고, 몇백 쪽짜리도 한 번에 넘어갑니다.
- **부르는 말** "PDF를 마크다운으로" · "이 PDF 텍스트 뽑아줘"
- **조심할 것** 변환은 파이썬이 하므로 대화 분량(토큰)을 잡아먹지 않습니다
- **누구에게** 기획·전략 · 디자인 · 생산·품질 · 사무·행정

#### 한글 문서 · `hwpxskill`
한글 문서를 만들고, 읽고, 고칩니다. 관공서 서식처럼 한글로 주고받는 문서를 Claude가 직접 다룰 수 있게 합니다.
- **부르는 말** "한글 파일로 만들어줘" · "이 hwpx 열어줘"
- **조심할 것** 본체는 **`.hwpx`** 형식입니다. `.hwp`(구버전)가 오면 먼저 hwpx로 바꿔야 하는데, 맥·리눅스에서는 한글에서 사람이 다시 저장해 주는 수밖에 없습니다(윈도우 + 한글이 깔린 기계는 스킬이 직접 바꿉니다 — SKILL.md 「워크플로우 0」)
- **누구에게** 사무·행정 · 총무·법무 · 교육·HR · 대표·팀장

#### 녹취 정리 · `transcript-organizer`
강의·미팅·인터뷰를 받아쓴 긴 텍스트를 구조를 잡아 정리합니다. 음성인식이 잘못 알아들은 말을 고치고, 글자가 깨진 파일도 살립니다.
- **부르는 말** "녹음 정리해줘" · "미팅록 만들어줘" · "이 txt 정리"
- **조심할 것** **녹음을 글로 바꾸는 건 이 스킬이 아닙니다.** 이미 받아쓴 txt를 넣으면 정리된 문서가 나옵니다. 임의로 줄이지 않고 원문 인용을 많이 남깁니다
- **누구에게** 교육·HR · 기획·전략 · 마케팅·홍보 · 대표·팀장

### 매일 기록

#### 데일리 노트 · `daily-note`
오늘 날짜 업무일지를 정해진 폴더에 만들고, 어제 노트·할 일 목록·최근에 고친 파일을 보고 오늘 먼저 할 일 3개를 골라 적습니다. 구글 캘린더를 연결해 두면 오늘 일정도 같이 적힙니다.
- **부르는 말** "오늘 daily note" · "하루 기록 시작" · "오늘 뭐부터 하지"
- **조심할 것** 이미 오늘 노트가 있으면 새로 만들지 않고 그 파일을 엽니다. 「오늘 할 일」이 이미 채워져 있으면 건드리지 않습니다. 캘린더 연결(`gws`)은 선택입니다 — 없으면 일정 칸만 빕니다
- **누구에게** 기획·운영 · 대표·팀장 · 인사·교육 · 프리랜서

#### 주간 정리 · `weekly-synthesis`
한 주 동안의 기록과 작업을 모아 하나로 묶습니다. 무엇을 했는지가 아니라 무엇이 남았는지가 나옵니다.
- **부르는 말** "주간 정리" · "이번 주 회고"
- **조심할 것** 금요일이나 일요일에 한 번 돌리는 용도입니다
- **누구에게** 대표·팀장 · 기획·운영 · 인사·교육 · 프리랜서

#### 할 일 · `todo`
말하는 대로 할 일을 담고, 꺼내 봅니다. 급한 것인지, 어느 프로젝트 것인지 알아서 붙여 두고, 볼 때는 오늘 것·프로젝트별·오래 묵은 것처럼 말한 대로 보여줍니다.
- **부르는 말** "이거 해야 해" · "기억해둬" · "할 일 추가" · "할 일 보여줘" · "오래된 할 일"
- **조심할 것** 마감일 개념은 없습니다. **담아 둔 지 1주일이 넘은 것**을 "오래된 것"으로 봅니다
- **누구에게** 전 직군

### 지식 쌓기

#### 위키에서 찾기 · `wiki-query`
쌓아 둔 위키에서 찾아 인용과 함께 답합니다. 주제·개념·과거 판단을 물으면 따로 부르지 않아도 켜집니다.
- **부르는 말** "위키에서 찾아줘" · "우리가 뭐라고 정리했더라"
- **조심할 것** 위키는 원본이 아니라 정리본입니다. 방향·판단은 그대로 써도 되지만 금액·날짜·이름은 근거에 적힌 원본 파일까지 열어 확인합니다
- **누구에게** 기획·전략 · 교육·HR · 대표·창업 · 콘텐츠·에디터

#### 위키에 쌓기 · `wiki-ingest`
흩어진 자료를 읽어서 주제별 위키 문서에 합칩니다. 덧붙이기만 하는 게 아니라 핵심을 다시 쓰고, 서로 연결하고, 앞뒤가 안 맞는 곳을 표시합니다.
- **부르는 말** "위키에 반영해줘" · "지식 축적"
- **조심할 것** 아는 것이 파일 개수가 아니라 한 장의 정리로 쌓입니다. `transcript-organizer`가 끝에서 이 스킬을 부릅니다
- **누구에게** 기획·전략 · 교육·HR · 대표·창업 · 콘텐츠·에디터

#### 위키 점검 · `wiki-lint`
쌓아 둔 위키를 훑어 문제를 찾습니다. 아무 데서도 연결 안 된 문서, 끊어진 링크, 오래 손 안 댄 문서, 서로 어긋나는 내용을 짚습니다.
- **부르는 말** "위키 점검" · "위키 헬스체크"
- **조심할 것** 한 달에 한 번쯤이면 충분합니다
- **누구에게** 기획·전략 · 교육·HR · 대표·창업 · 콘텐츠·에디터

### 일 굴리기

#### 프로젝트 7단계 · `do-better-drive`
프로젝트 하나를 목적부터 끝까지 일곱 단계로 밉니다 — 프레임 → 될 일인가 → 계획 → 생산 → 검토 → 내보내기 → 돌아보기.
- **부르는 말** "새 프로젝트 시작" · "이거 할까 말까" · "냉정하게 봐줘" · "회고"
- **조심할 것** **앞 세 단계에서는 아무것도 만들지 않습니다.** 될 일인지부터 봅니다. 어느 단계에나 바로 들어갈 수 있습니다
- **누구에게** 대표·창업 · 기획·전략 · PM·PO · 프리랜서

#### 같이 생각하기 · `thinking-partner`
답을 바로 주는 대신 질문을 던져 생각을 밀어 줍니다. 뭘 해야 할지 모르겠을 때, 답이 아니라 질문이 필요할 때 씁니다.
- **부르는 말** "고민이 있어" · "같이 생각해보자" · "생각 정리 도와줘"
- **누구에게** 대표·창업 · 기획·전략 · 인사·교육 · 프리랜서

#### 세션 마무리 · `ripple`
대화를 닫기 전에 한 번 치면, 이 대화에서 내가 한 말을 처음부터 다시 훑어 남길 것을 제자리에 적습니다 — 오늘 노트(완료한 일·배운 것·내일 이어갈 것), 프로젝트 진행 기록, 할 일, 정한 것과 그 이유, 고친 파일과 연결된 문서. 끝에 빠진 말이 없는지 짝을 맞춥니다.
- **부르는 말** "ripple" · "이 대화 기록해줘" · "마무리하자" · "빠진 거 없나"
- **조심할 것** 쓰기 전에 표로 보여주고 묻습니다. 위키는 제안까지만 합니다(쓰는 건 `wiki-ingest`). 파이썬이 있어야 내가 한 말을 기록에서 뽑습니다
- **누구에게** 전 직군

#### 이어서 하기 · `handoff`
대화가 길어지면 Claude가 한 번에 볼 수 있는 분량(콘텍스트)이 차고, 차면 앞에서 나눈 이야기부터 요약되어 줄어듭니다. 그래서 일이 길어지면 분량이 차기 전에 대화를 비우고 새 대화에서 이어가는데, 그때마다 목표와 지금까지 한 일을 다시 설명하기는 번거롭습니다. 이 스킬은 대화를 비우기 전에 목표와 어디까지 했는지를 작업 파일 하나에 적어 두고, 새 대화가 그 파일을 읽어 같은 목표로 일을 이어가게 합니다. 그동안 직접 계속 쓰면서 다듬어 온 스킬이고, 이제 공유할 만해져서 넣었습니다.
- **부르는 말** "핸드오프" · "맥락 넘겨줘" · "이어서 할 수 있게" — 이어받을 때는 새 대화 첫 메시지로 `/handoff 재개`
- **조심할 것** 작업 하나에 파일 하나입니다(`00-system/06-handoffs/`). 넘길 때마다 새 파일을 만들지 않고 같은 파일을 이어 씁니다 — 목표는 그대로 두고 지금 상태만 갈아끼웁니다. 파이썬이 필요합니다(추가 설치는 없음) — 칸이 비었거나 너무 길면 저장을 거부하고 무엇을 고칠지 알려줍니다
- **누구에게** 전 직군

#### 대시보드 기획 · `dashboard-prd`
어떤 대시보드를 만들지 물어보면서 기획서를 같이 씁니다. 무슨 숫자를 어떤 화면으로 볼지가 문서로 남습니다.
- **부르는 말** "대시보드 기획" · "현황판 만들고 싶어"
- **조심할 것** 매출·발주·재고 현황판을 만들기 **전** 단계입니다
- **누구에게** 대표·팀장 · 영업·정산 · 이커머스·MD · 생산·재고

#### 웹앱 기획 · `webapp-prd`
내 업무에 필요한 웹앱을 어떻게 만들지 물어보면서 기획서를 같이 씁니다. 만들기 전에 무엇을 만들지부터 정합니다.
- **부르는 말** "웹앱 만들고 싶어" · "앱 설계"
- **조심할 것** 이 문서를 넘기면 Claude가 실제 화면을 만들기 시작합니다
- **누구에게** 대표·창업 · 기획·전략 · PM·PO · 프리랜서

## 헷갈리는 짝

이름만 보면 비슷해 보이는 것들입니다. 갈리는 지점만 적었습니다.

**`naver-search` vs `review-analyzer`** — 앞은 **검색 데이터**(몇 명이 뭘 검색하는지), 뒤는 **리뷰**(산 사람이 뭐라고 했는지). 시장이 있는지 보려면 앞, 무엇을 고칠지 찾으려면 뒤.

**`web-bypass` vs 그냥 요약** — 막혀서 안 열리면 앞, 읽고 요약만 할 거면 스킬이 필요 없습니다(그냥 주소를 주고 요약해달라고 하면 됩니다).

**`daily-note` vs `weekly-synthesis`** — 앞은 **오늘 뭘 먼저 할지**(아침), 뒤는 **한 주에 뭐가 남았는지**(주말).

**`transcript-organizer` vs 녹음 앱** — 이 스킬은 **이미 글로 받아쓴 파일**을 정리합니다. 음성을 글로 바꾸는 건 폰 녹음기나 받아쓰기 앱이 합니다.

**`ripple` vs `handoff`** — 앞은 **이 대화에서 나온 것을 노트·진행 기록·할 일에 나눠 적기**(대화를 닫기 전), 뒤는 **하던 일 하나를 다음 대화로 통째로 넘기기**. 일을 마무리할 때는 앞, 대화가 길어져 비우고 이어갈 때는 뒤. 둘 다 해도 됩니다.

- 엑셀·CSV 작업 (스킬 없음 — Claude가 코드를 짜서 처리) — pandas · openpyxl
- `pdf-to-md` — pymupdf4llm
- `hwpxskill` — lxml · python-hwpx (`python -m pip install -r .claude/skills/hwpxskill/scripts/requirements.txt`). `.hwp`를 직접 여는 건 **윈도우 + 한글 설치** 기계에서만 되고 그때 `requirements-windows.txt`(pyhwpx)를 더 깐다
- `review-analyzer` — **상품 리뷰(브랜드스토어)만** selenium (+ Chrome 브라우저)이 필요하다. `--no-login`은 이것만 필요. **매장 리뷰(플레이스)는 의존성이 없다**(파이썬 표준 라이브러리) — `--deep`일 때만 playwright. 로그인·시트 업로드는 선택 의존(주석 참조: `scripts/requirements.txt`)
- `naver-search` — **없음** (파이썬 표준 라이브러리만). 대신 API 키가 필요하다: NAVER API HUB(ncloud) 필수, 검색광고 API(searchad.naver.com)는 검색량·연관키워드를 쓸 때만. `scripts/.env.example`을 `.env`로 복사해 채운다 — 키는 각자 본인 계정으로 발급

## 설치가 필요한 스킬 (시스템 도구·플랫폼)

- `web-bypass` — 파이썬 패키지는 없다(표준 라이브러리만). 뒤의 두 단계에 Aside 앱과 `aside` 명령이 필요하다(캠프 설치 안내에서 깐다)
- `kakao-read` — **Mac·윈도우 둘 다 됩니다. 읽는 방식이 다릅니다.** Python 패키지 의존은 없음(양쪽 다 표준 라이브러리만).
  - **Mac**: 카톡의 암호화된 로컬 DB를 직접 읽습니다. 시스템 도구 `sqlcipher`가 필요:
  ```bash
  brew install sqlcipher
  # 최초 1회 본인 userId 캐시 (워크스페이스 루트에서)
  python3 .claude/skills/kakao-read/scripts/kakao_read.py setup
  ```
  카카오톡 데스크톱 앱에 한 번 이상 로그인돼 있어야 한다. 설정은 `~/.config/kakao-read/`(HOME)에 저장 — 워크스페이스 밖이라 git 추적 안 됨.
  - **윈도우·WSL**: 실행 중인 카톡의 메모리를 읽습니다. `sqlcipher`도 키도 필요 없고, **읽는 순간 카톡이 켜져 있어야** 합니다. 윈도우에는 파이썬이 기본으로 없으니 없으면 먼저 설치하세요(`winget install --id Python.Python.3.12 -e`). 절차는 SKILL.md의 "윈도우 카톡 읽기" 절에 있습니다.
  - 그 밖의 OS(순수 리눅스)에서는 안 됩니다 — 다른 스킬엔 영향 없습니다.

**권장 세팅 (워크스페이스 전용 venv)**:

```bash
# 워크스페이스 루트에서 1회 실행
python3 -m venv .venv        # 윈도우에는 python3 가 없을 수 있다 → python 또는 py
source .claude/venv.sh
python -m pip install pandas openpyxl -r .claude/skills/pdf-to-md/scripts/requirements.txt
```

이후 Python 스킬을 쓸 때마다 `source .claude/venv.sh` 한 번 실행 (Mac·윈도우 공통). 활성화 뒤에는 `python3`가 아니라 **`python`**으로 부른다. `.venv/`는 `.gitignore` 처리됨.

**venv 없이 직접 설치하려면** (Python 3.12+ / Homebrew 환경에서는 PEP 668 때문에 실패할 수 있음):

```bash
python -m pip install pandas openpyxl
# 실패 시: python -m pip install --user ... 또는 pipx 고려
```
