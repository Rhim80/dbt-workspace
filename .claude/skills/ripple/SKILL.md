# ripple — 대화를 닫기 전에 남길 것을 전부 남긴다

새 대화는 지난 대화를 기억하지 못한다. 파일에 남지 않은 것은 없던 일이 된다. ripple은 이 대화에서 나온 것 중 다시 쓸 것을 **제자리에** 옮겨 적는다.

빠뜨리는 이유는 둘이다. 대화가 길면 앞부분이 요약되어 기억에서 먼저 사라지고, 파일을 안 고친 대화(정하기만 한 대화)는 흔적이 없다. 그래서 **기억이 아니라 목록에서 출발하고, 자리를 매번 전부 훑고, 끝에 짝을 맞춘다.**

## 1. 재료 모으기 — 기억이 아니라 목록으로

**사용자가 한 말** — 처음부터 시간순으로 뽑아 끝까지 읽는다.

```bash
PY=""; for c in python3 python py; do "$c" -c 'import sys; assert sys.version_info >= (3, 9)' 2>/dev/null && { PY="$c"; break; }; done
"$PY" .claude/skills/handoff/scripts/handoff.py said
```

0건이거나 실행이 안 되면 "말이 없었다"로 읽지 않는다 — 그 사실을 알리고, 지금 보이는 대화에서 뽑는다(앞부분이 요약됐으면 빠졌을 수 있다고 함께 말한다).

**이 대화에서 고친 파일** — 기억한 목록을 아래 출력과 대 본다. 기억에 없는데 오늘 바뀐 파일이 있으면 이 대화에서 고친 것인지 확인한다.

```bash
git status --short 2>/dev/null
find 00-inbox 10-projects 20-operations 30-knowledge 40-personal 50-resources -type f -mtime -1 -not -name ".DS_Store" 2>/dev/null
```

## 2. 자리마다 판정 — 하나도 건너뛰지 않는다

아래 여섯 자리를 매번 전부 본다. 자리마다 **"적을 것"** 또는 **"해당 없음 — 이유 한 줄"** 중 하나를 낸다. 판정 없이 넘어가는 자리가 없어야 한다.

| 자리 | 무엇을 | 어디에 |
|---|---|---|
| ① 오늘 노트 | 끝낸 일 · 알게 된 것 · 다음에 이어갈 것 | `40-personal/41-daily/YYYY-MM/YYYY-MM-DD.md`의 「완료한 일」「배운 것 / 인사이트」「내일 이어갈 것」. 노트가 없으면 `daily-note` 템플릿으로 만들지 묻는다 |
| ② 진행 기록 | 이 대화가 다룬 프로젝트의 한 일·지금 상태·다음 한 걸음 | `10-projects/<프로젝트>/progress.md` — 형식은 아래 「진행 기록」 |
| ③ 할 일 | 대화에서 나온 "나중에 할 것", 이번에 끝낸 할 일 | `40-personal/46-todos/active-todos.md` — 형식은 `todo` 스킬. 끝낸 것은 체크 |
| ④ 정한 것과 이유 | 고른 것·버린 것과 그 이유 (사용자 말이 있으면 원문으로) | 그 프로젝트 `progress.md` 로그. 이 일의 핸드오프 파일(`00-system/06-handoffs/`)이 있으면 그 「판단」 칸에도 |
| ⑤ 위키 거리 | 이 대화를 넘어 다시 꺼내 쓸 앎 | **제안만** 한다 — 넣는 것은 `wiki-ingest`. `30-knowledge/00-wiki/index.md`를 보고 어느 토픽에 무엇을 넣을지 구체적으로 |
| ⑥ 연결 문서 | 고친 파일 이름을 가리키는 다른 문서, 스킬·에이전트를 고쳤으면 목록(README) | 워크스페이스 전체를 이름으로 검색 (`90-archive/`·`.git/`·`.venv/` 제외) |

판정 기준:

- **프로젝트를 고른다** — 고친 파일이 `10-projects/` 아래면 그 프로젝트. 파일은 안 고쳤어도 대화에서 그 프로젝트 이름이 나오고 무언가 정해졌으면 그 프로젝트도 대상이다
- **같은 내용을 두 곳에 길게 쓰지 않는다** — 자세한 건 한 곳(보통 `progress.md`)에, 오늘 노트에는 한 줄 + 그 파일 경로
- **근거가 없는 줄은 쓰지 않는다** — 적는 줄마다 사용자 말이나 파일·명령 결과 중 어디서 왔는지 댈 수 있어야 한다. 이름·금액·날짜는 원본 파일에서 다시 확인한다
- **잡담·질문·이미 파일에 남은 것은 기록하지 않는다** — "해당 없음"으로 적고 넘어간다

## 3. 표로 보여주고 묻는다

```
| 자리 | 적을 것 (한 줄) | 근거 |
|---|---|---|
| ① 오늘 노트 · 완료한 일 | 스킬 7개 정리, 캠프 노션 6쪽 수정 | 말 [3][7], 커밋 3개 |
| ② 진행 기록 | 해당 없음 — 10-projects 아래 일이 아님 | |
| ③ 할 일 | 기획서 스킬 두 개 다시 볼 것 | 말 [4] "나중에 이야기하자" |
…
```

"해당 없음"인 자리도 표에 남긴다(빠뜨린 것과 볼 것이 없던 것을 구분하려고). 어느 것을 쓸지 묻는다 — 전부·골라서·안 함.

## 4. 승인한 것만 쓴다

- 필요한 만큼만 최소로. 기존 내용을 지우거나 고쳐 쓰지 않고 더한다
- 오늘 노트가 없고 만들기로 했으면 `00-system/01-templates/daily-note-template.md`로 만든다
- 할 일은 `todo` 형식(`added`·`priority`)을 지킨다
- 위키는 쓰지 않는다 — 좋다고 하면 `wiki-ingest`를 부른다

### 진행 기록 (`progress.md`)

형식의 원본은 `00-system/01-templates/progress-template.md`다(`do-better-drive`와 같은 양식). 여기 베끼지 않는다 — 그 파일을 읽고 맞춘다.

- **이미 있는 파일**: `## 로그`에 `- YYYY-MM-DD <한 일> (ripple)` 한 줄을 더하고, `## 지금 상태`·`## 다음 한 걸음`을 이번 대화 기준으로 고치고, 머리의 `updated:`를 오늘로. **`status:`는 바꾸지 않는다** — 단계 판정은 `do-better-drive`의 몫이다
- **옛 형식 파일**(`## 타임라인` 표)이면 그 표에 행을 더하고 "최근 업데이트" 날짜만 바꾼다. 형식을 몰래 바꾸지 않는다
- **없는 파일**: 만들지 묻는다. 만들면 템플릿을 복사해 `[프로젝트명]`·날짜를 채우고, `## 목표`(대화에서 나온 만큼)·`## 지금 상태`·`## 다음 한 걸음`·`## 로그`만 채운다. 나머지 칸과 `status:`는 비워 둔다(`do-better-drive`가 들어오면 ① 프레임부터 한다). 위치는 프로젝트 루트(`10-projects/<프로젝트>/`)에 한정한다

## 5. 빠짐 검사 — 끝에 짝을 맞춘다

1단계에서 뽑은 사용자 말을 하나씩 보고, 각 말이 어느 자리에 들어갔는지 짝을 짓는다. **아무 자리에도 안 들어간 말 중 요청·결정·나중 할 일이 있으면** 따로 보여주고 어디에 넣을지 묻는다. 질문·잡담·이미 처리돼 파일에 남은 요청이면 "기록 불필요"로 둔다.

마지막에 한 줄로 알린다 — 쓴 자리, 안 쓴 자리(사용자가 뺀 것), 남은 위키 제안.

## 원칙

- **기억이 아니라 목록에서 출발한다** — 사용자 말 목록과 바뀐 파일 목록
- **여섯 자리를 매번 전부 본다** — "해당 없음"도 판정이다
- **보여주고 물은 뒤 쓴다** — 거절하면 아무것도 안 바뀐다
- **ripple이 맡지 않는 것** — 다음 대화로 넘길 작업 맥락 전체는 `handoff`, 위키 쓰기는 `wiki-ingest`, 프로젝트 단계 판정은 `do-better-drive`
