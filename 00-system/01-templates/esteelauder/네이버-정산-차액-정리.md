# 네이버 정산 차액 정리 템플릿

> 한 달 치 내부 정산 데이터와 네이버 정산 파일을 맞대어, 차액을 사유별로 나누고 추가 조정(ZCM·ZDM)이 필요한 건을 가려 재무팀에 넘길 한 장을 만들 때 쓰는 양식.
> 호출: `@templates/esteelauder/네이버-정산-차액-정리.md 관점으로`

---

## 사용 데이터

| 파일 | 왜 필요한가 |
|------|------------|
| `내부_정산데이터_네이버_10월.csv` | 우리 쪽 기록. OMS 주문을 SAP 매출로 올린 값이다. **주문일 기준으로 10월에 묶여 있다.** `OMS상태`·`오더유형`·`SAP역분개`·`구매확정일`이 차액 사유를 가르는 열이다 |
| `네이버_정산내역_10월.csv` | 네이버 쪽 기록. **정산기준일(구매확정일)이 10월인 상품주문만** 들어 있다. 구매확정 전에 취소·반품된 주문(정산 전 취소)은 이 파일에 아예 없다. 상품은 `상품번호`(네이버 상품번호)로만 나온다 |
| `상품마스터.csv` | SKU별 SAP자재코드·네이버상품번호·정가·네이버 판매가. **`판매가변경일`이 있는 SKU는 그날부터 네이버 판매가가 `변경후판매가`로 바뀐 것**이다 |
| `프로모션_쿠폰_10월.csv` | 10월에 걸린 쿠폰. `판매자부담비율`이 우리 매출에서 빠져야 하는 몫이다. `OMS연동`은 그 쿠폰 할인이 OMS 주문에 실려 내부 데이터로 넘어오는지다 |

**파일 사이를 잇는 키**: `상품주문번호` (두 정산 파일 공통) · `SKU코드` (내부 ↔ 마스터) · `상품번호` = 마스터 `네이버상품번호` (네이버 ↔ 마스터) · `쿠폰ID` (네이버 ↔ 쿠폰표)

정산 파일 두 개만 보면 "차액이 OO원"에서 끝난다. 이 정리가 답해야 하는 질문은 *"차액이 왜 생겼고, 그중 무엇을 SAP에서 고쳐야 하고, 무엇은 다음 달에 저절로 풀리는가"* 다. 네 파일을 다 붙인다.

**계산 규칙** (이 순서로 한다):

```
비교 기준 매출   내부: 내부매출금액            (= 단가 × 수량 − 내부할인)
                 네이버: 상품금액 − 판매자부담할인   (= 결제금액 + 네이버할인지원금)
                 → 네이버할인지원금은 네이버가 채워 주므로 우리 매출이다
                 → 수수료(Npay수수료·판매수수료)는 비교에서 뺀다. 차액 사유가 아니라 정해진 비용이다
차액             = 내부 비교 기준 매출 − 네이버 비교 기준 매출   (+면 내부가 많다)

1단계  상품주문번호로 두 파일을 붙인다 → 양쪽에 다 있음 / 내부에만 / 네이버에만
2단계  내부에만 있는 줄
         오더유형 = 교환재발송                          → 교환
         OMS상태 = 취소완료·반품완료, SAP역분개 = N       → 취소·반품 (역분개 누락)
         OMS상태 = 반품요청                            → 취소·반품 (진행 중)
         구매확정일이 비었거나 11월                      → 익월 정산
3단계  네이버에만 있는 줄 → 결제일이 9월이면 전월 주문분
4단계  양쪽에 다 있고 금액이 다른 줄
         네이버 판매자부담할인 > 내부할인, 쿠폰ID 있음      → 쿠폰·할인
         내부 단가 ≠ 네이버 판매가, 마스터에 판매가변경일 있음 → 판매가 변경 미반영
5단계  어디에도 안 맞는 줄 → 미분류 (원인을 지어내지 않는다)
```

- **한 줄에 두 사유가 겹치면 금액을 사유별로 나눠 넣는다.** 쿠폰 몫(판매자부담할인 − 내부할인)을 먼저 떼고, 남은 금액을 판매가 몫((내부 단가 − 네이버 판매가) × 수량)과 대본다. 그 줄에는 "겹침"이라고 표시한다.
- 사유별 차액을 다 더하면 **전체 차액과 1원 단위까지 같아야 한다.** 다르면 표를 내지 말고 어디서 어긋났는지부터 적는다.
- 금액 합계는 계산 코드로 낸다. 눈으로 더한 값을 쓰지 않는다.
- 회사에서 부르는 사유 이름(예: "네이버 분리 정산")과 이 양식의 이름이 다를 수 있다. 같은 것인지 확인 안 된 이름은 **"(회사 용어와 대조 필요)"**를 붙인다.

## 출력 구조

### 1. 한 줄 결론

형식: "10월 차액은 OO원(내부가 많음/적음)이고, 그중 OO원은 SAP 조정이 필요하며 OO원은 11월 정산에서 풀린다. 원인을 모르는 차액은 OO원 · O건이다."

숫자 세 개(전체 · 조정 필요 · 미분류)가 문장 안에 다 있어야 한다.

### 2. 차액 다리

내부 합계에서 출발해 사유별로 더하고 빼서 네이버 합계에 닿는 표. HTML이면 폭포형 막대(내부 → 사유들 → 네이버)로, 마크다운이면 표로.

| 단계 | 금액(원) | 건수 | 그래서 |
|------|---------|------|--------|
| 내부 비교 기준 매출 | | | |
| − 익월 정산 | | | |
| − 취소·반품 | | | |
| − 교환 | | | |
| − 쿠폰·할인 | | | |
| ± 판매가 변경 미반영 | | | |
| + 전월 주문분 | | | |
| ± 미분류 | | | |
| = 네이버 비교 기준 매출 | | | |

- **"그래서" 칸은 비우지 않는다.** 그 사유가 SAP 조정 대상인지, 다음 달에 풀리는지, 누구 확인이 필요한지 한 줄.
- 마지막 줄이 네이버 파일 합계와 다르면 다리가 끊긴 것이다. 끊긴 채로 내지 않는다.

### 3. 사유별 원인 — 사유 하나에 3~4줄

- **얼마나** — 금액·건수, 전체 차액에서 차지하는 몫(%)
- **어디에 몰렸나** — SKU·날짜·쿠폰 중 몰린 곳. 예: "OO 쿠폰 기간 7일에 쿠폰 차액의 OO%"
- **왜 생겼나** — 데이터에서 보이는 것만. 시스템이 왜 그렇게 동작했는지는 데이터로 알 수 없으므로 **"(추정)"**을 붙이거나 "확인 필요"로 둔다
- **다음 달에도 생기나** — 같은 구조가 11월에도 반복될지. 쿠폰·가격 변경이 계속되면 "반복", 한 번 일이면 "일회성 (추정)"

### 4. 조정 판단 — 세 칸으로 나눈다

| 구분 | 사유 | 금액 | 건수 | 근거 |
|------|------|------|------|------|
| **조정 필요** | | | | |
| **조정 불필요** | | | | |
| **확인 필요** | | | | |

- 내부 매출이 많으면 감액 조정(ZCM), 적으면 증액 조정(ZDM)으로 적는다. **ZCM·ZDM의 뜻은 이 양식의 가정이다 — 회사 전표 기준과 다르면 바꿔 쓴다.**
- **익월 정산은 조정 불필요**로 두되, 11월 정산 파일에서 다시 볼 상품주문번호 목록을 붙인다.
- **반품요청(진행 중)·전월 주문분·미분류는 확인 필요.** 반품이 실제로 입고됐는지, 9월 내부 데이터에 이미 잡혔는지는 이 파일들로 알 수 없다. 파일로 알 수 없는 것을 "조정 필요"로 올리지 않는다.
- 조정 필요 칸은 **SKU별 합계 표**를 따로 붙인다 — 재무팀이 전표를 칠 단위다.

### 5. 미분류 목록

미분류 줄은 전부 나열한다. 상품주문번호 · SKU · 내부 금액 · 네이버 금액 · 차액 · "확인해 볼 곳" 한 줄. 몇 건이든 생략하지 않는다. **미분류가 0건이어도 "0건"이라고 적는다.**

### 6. 재무팀 공유 코멘트 3종

- **숫자형** — 조정 금액과 건수를 앞세운 문장
- **흐름형** — "이 일 때문에 이 차액이 생겼고 이렇게 고친다"
- **헤드라인형** — 이번 달 차액을 한 구절로

셋 다 채우고, 아래에 `작성자 코멘트:` 칸을 비워 둔다.

### 7. 다음 달 전에 할 일

| 담당 | 할 일 | 기한 | 우선순위 | 성공 기준 |
|------|------|------|---------|----------|

- 3~5건. 담당은 역할로 (온라인 PMO / OMS 운영 / 온라인팀 / 재무팀). 사람 이름은 쓰지 않는다
- **성공 기준은 숫자로.** "개선"이 아니라 "11월 쿠폰 차액 0원", "역분개 누락 0건"
- 우선순위는 1·2·3 순번. 동점 없음

## 검출 규칙

이 값에 걸리면 보고서에 **반드시 올린다.**

| 신호 | 임계값 | 어느 섹션 |
|------|--------|----------|
| 다리 끊김 | 사유별 합 ≠ 전체 차액 (1원이라도) | §2 앞에 경고 |
| 쿠폰 쏠림 | 한 쿠폰이 쿠폰 차액의 **50% 이상** | §3 |
| 역분개 누락 | OMS 취소·반품완료인데 SAP역분개 = N **1건 이상** | §3, §4 조정 필요 |
| 이중 매출 | 교환재발송 줄에 금액이 있음 **1건 이상** | §3, §4 조정 필요 |
| 가격 미반영 | 판매가변경일 뒤 주문인데 단가가 변경 전 값 **1건 이상** | §3, §4 |
| 수수료율 이상 | 줄별 Npay수수료 ÷ (결제금액 + 네이버할인지원금)이 3.63%, 또는 판매수수료 ÷ 결제금액이 유입구분별 값(네이버쇼핑 4% · 판매자마케팅 링크 2%)에서 **0.05%p 넘게** 벗어남 | §5 옆에 참고 |
| 미분류 비중 | 미분류 금액이 전체 차액 절댓값의 **5% 이상** | §1에 명시 |

**걸린 것이 하나도 없으면 "이번 달 임계값 초과 없음"이라고 적는다.**

## 길이 제약

**본문 A4 1장(§1·§2·§4·§6) + 부록(§3·§5·§7·SKU별 조정표).** 본문 한 장만 떼어 재무팀에 보내도 무엇을 고칠지 알 수 있어야 한다.

- 줄여도 되는 것: 부록 표의 행 수(상위 10개 + "외 O건")
- **줄이면 안 되는 것: §2의 "그래서" 칸, §4의 "확인 필요" 칸, §5 미분류 전체 목록.** 분량이 넘치면 표 행을 줄이지 해석을 줄이지 않는다

## 톤 가이드

**온라인 PMO가 재무팀에 넘기는 정산 조정 근거**다. 읽는 사람은 SAP 전표를 치는 사람이고, 숫자 하나하나를 전표로 옮긴다.

- **숫자 옆에는 의미가 붙는다.** "쿠폰 차액 OO원"이 아니라 "쿠폰 차액 OO원 — OMS연동이 N인 쿠폰의 판매자 부담분이 내부 데이터에 안 넘어와서, ZCM 대상"
- **데이터에 없는 사유를 쓰지 않는다.** 시스템 동작을 상식으로 설명하지 않는다. 추정은 "(추정)"
- **확정과 미확정을 섞지 않는다.** 확인 필요 칸에 있는 것을 결론 문장에 넣지 않는다
- 금액은 원 단위, 천 단위 쉼표. 건수는 "건"
- 평서체
